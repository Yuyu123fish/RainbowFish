# RainbowFish · 虹忆

RainbowFish 是以统一、可追溯的多模态长期记忆为核心的个人 Agent 系统。它面向个人开发和知识管理：用户可以在虹忆中讨论项目、积累记忆，未来也可以让外部 Agent 使用同一套记忆，接续已有工作。

项目目前处于文档与设计阶段，**尚无应用代码、已安装依赖或启动命令**。下面的能力是已确认的开发方向，均未实现；具体交互和验收条件将在各阶段的 Feature 中确定。

## 要解决的问题

项目背景、设计决定和任务结论常散落在不同 Agent 的会话里。换会话或换工具后，用户需要重新交代背景，也不容易判断旧结论是否已被纠正。虹忆计划把对话、资料和记忆关联起来，让后续任务既能找到相关信息，也能回看形成结论的依据。

## 计划中的能力

开发按以下顺序推进：

1. **基础对话与项目管理**：创建项目和会话，调用模型对话，保存并重开历史。
2. **文本记忆**：从对话和文字资料保存记忆，按个人或项目范围检索、回读来源、修改和纠正。
3. **接入一个外部 Agent**：从 Codex、Claude Code、pi 中选择首个宿主，让它读写同一套记忆；宿主尚未选定。
4. **项目会话关联与发现**：关联具体外部会话，查看列表、摘要和来源，按需读取相关讨论。
5. **完善虹忆自身的任务执行**：按需使用工具与 Skill，查看执行过程、结果和产物，并积累有价值的记忆。
6. **多模态资料与记忆**：先支持图片，再扩展到音频、视频，并能回读原始材料或对应片段。
7. **可视化工作流**：将已可用的模型、工具、Skill 和记忆操作组织为节点，连线执行并查看结果。

**首个可用目标是第 1、2 阶段**：在虹忆中讨论项目、保存决定，换会话后仍能找回、核对和纠正。第 3、4 阶段再验证跨 Agent 接续。外部会话的主动通讯和唤醒不属于当前已确定的能力。

## 技术方向

已选择 TypeScript、Node.js LTS 和 pnpm workspace 作为主栈，Electron、React 用于桌面端，SQLite 用于业务数据。计划使用 AI SDK Core 支撑模型调用，Drizzle 与 better-sqlite3 访问数据库，FTS5 和 sqlite-vec 支撑检索；外部接入方向包括 Hono 与 MCP TypeScript SDK，可视化节点编辑选择 React Flow。这些依赖尚未安装，版本与兼容性仍待工程初始化时验证。

## 仓库约定

GitHub 仓库：[Yuyu123fish/RainbowFish](https://github.com/Yuyu123fish/RainbowFish)，主分支为 `main`。

- `docs/` 保存项目介绍、技术栈和架构说明；`specs/` 保存功能路线、开发流程和具体工作记录。
- 本地环境配置、数据库、运行数据和原始媒体不进入版本库。开发时需要存放在仓库内的运行数据统一放入根目录 `data/`；应用正式数据位置在后续 Feature 中确定。
- 环境配置示例仅填写占位值，锁文件和数据库迁移文件应随代码提交。
- 文本文件默认使用 LF，PowerShell、批处理脚本使用 CRLF。
