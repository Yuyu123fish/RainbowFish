# RainbowFish · 虹忆

## 项目定位

RainbowFish 是以统一、多模态长期记忆为核心的个人 Agent 系统。

用户可以直接与它对话、使用工具和完成任务，也可以让 Codex、Claude Code、pi 等 Agent 接入同一套记忆。记忆围绕用户和项目积累，保留来源、时间和适用范围。

这是一个个人长期项目。当前主要考虑个人开发和知识管理场景，以及桌面端的使用体验。

## 要解决的问题

一次讨论的结论可能留在某个 Agent 的某个会话中。换工具、换会话之后，用户需要重新交代项目背景，也很难判断旧结论是否已经被替代。

资料还可能分散在文档、截图、录音和视频中。只保留文字摘要，会丢掉后续核对所需的细节；只保存原文件，又不方便在任务中找回相关信息。

RainbowFish 希望把这些材料、讨论和记忆关联起来，让用户和接入的 Agent 能找到当前相关的信息，并回看形成结论的依据。

## 面向谁

- 项目的主要使用者是开发者本人，用于积累项目背景、设计决定、个人偏好、学习材料和任务经验。
- 外部 Coding Agent 是记忆与会话接口的调用方，各宿主按实际能力接入。
- RainbowFish 自带的 Agent 也是这些能力的使用者，用户可以直接在其中工作。

当前没有确定多人团队服务或 SaaS 产品范围。

## 已确定的能力方向

下表描述长期产品方向。已确认的开发顺序见[功能开发路线](../specs/roadmap.md)，首个可用版本以基础对话、项目管理和文本记忆为目标，具体范围在对应 Feature 中细化。

| 方向 | 预期用途 |
| --- | --- |
| 统一记忆 | 保存、检索、更新和纠正用户与项目记忆，保留可追溯的依据。 |
| 多模态资料与记忆 | 管理文本、图片、音频和视频，关联原始材料及具体证据位置。 |
| 独立 Agent | 提供对话、工具调用和任务执行能力，让用户不依赖其他 Coding Agent 也能使用。 |
| 外部 Agent 接入 | 优先面向 Codex、Claude Code、pi 提供共享记忆和上下文。 |
| 项目会话关联 | 关联具体宿主会话，使其他 Agent 能发现相关讨论，并按需读取记录与进展。 |
| Skill 扩展 | 用指令、参考资料、模板及必要脚本组织具体任务的方法。 |
| 可视化工作流 | 通过拖拽节点和连线编排明确的步骤，并查看执行结果。 |

## 典型使用过程

### 在不同 Agent 之间接续项目

用户在一个 Agent 中讨论项目方案，将该会话关联到 RainbowFish 的项目。另一个 Agent 开始相关工作时，查找关联会话，先了解摘要与进展，再读取必要的原始讨论。

用户纠正某项决定后，后续召回应能够取得更新后的结论及依据。运行中的其他会话是否立即刷新，不属于当前已经确定的承诺。

### 直接在 RainbowFish 中工作

用户在 RainbowFish 中上传资料、讨论问题、调用工具并保存产物。有价值的结论可以进入记忆，原始材料仍可回读。

稳定、反复使用的步骤可以组织为工作流；具体任务的方法可以通过 Skill 调整。

## 记忆要保留的区别

- 会话记录保留当时的讨论；长期记忆保留适合后续复用的信息。
- 用户明确表达、材料记载和模型推断分别记录，不能混成同一种事实。
- 计划、正在进行的工作和已经完成的结果有不同状态。
- 新上传的材料不一定描述更新的事实，信息更新需要结合证据与适用范围判断。
- 多模态摘要帮助检索和理解；需要具体细节时，可以回读原图、文档位置或音视频片段。

## 当前仍待确定

- 各阶段的具体交互、验收条件，以及首个外部 Agent 宿主和后续宿主的接入顺序。
- 对外接口的详细合同、自动采集时机与不同宿主的接入深度。
- 工作流节点类型、执行规则和恢复方式。
- 记忆更新、冲突处理及模型选择的具体实现。
- 向指定外部会话主动投递消息、等待回复或唤醒 Agent 的机制。

“Jev 判断组件”和“自我模型、自我监控”来自早期讨论，仍属于探索项，不纳入当前确定功能。OpenViking 是研究参考，尚未决定集成其实现。
