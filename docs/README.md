# RainbowFish · 虹忆文档

RainbowFish 是以统一、多模态长期记忆为核心的个人 Agent。它既面向用户独立完成任务，也为其他 Agent 提供记忆和相关会话上下文。

## 当前进度

截至 2026-10-06，项目已确定产品方向、基础技术栈和功能开发顺序，并建立 Git 与 [GitHub 仓库](https://github.com/Yuyu123fish/RainbowFish)，主分支为 `main`。当前内容为项目文档和仓库配置，尚无应用代码、依赖清单、数据库、测试脚本或 CI/CD。

文档中的功能描述是产品目标，技术栈是后续实施基线，都不表示对应能力已经实现。首个可用版本以基础对话、项目管理和文本记忆为目标；具体 Feature 的范围和验收条件仍需细化。

## 文档维护

- 产品定位和能力范围以项目介绍为准；技术选择以技术栈文档为准；职责和数据关系以架构文档为准。
- 开发流程规定步骤和完成条件，Agent 执行规则补充执行、协作和授权约束。
- 功能开发路线记录已确认的功能顺序和阶段目标，具体 Feature 在此基础上细化。
- `docs/` 保存项目介绍、技术栈和架构说明；根目录的 `specs/` 保存功能开发路线、开发流程、Agent 执行规则、模板与具体 Feature 文档。
- 具体需求的范围、实现方案和验证证据放在 `specs/<编号-名称>/` 下，目录规则见开发流程。当前不预建空 Feature。
- 修改已确定的方向时，先说明变更理由和影响，再更新对应文档。一次具体实现的结果不能悄悄替代产品决策。
- 验证记录区分已执行、未执行和受阻；示例、计划、模板不能作为实现或验收证据。
- 调整文件名或目录时，同步修正入口和相对链接。结束一次 Feature 时，用简短 Summary 留下结果和后续事项。
